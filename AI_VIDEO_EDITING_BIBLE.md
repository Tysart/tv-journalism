## 1. Подготовка машины: что должно быть установлено

Для работы конвейера на macOS (Apple Silicon M1/M2/M3/M4) или Linux-сервере необходимы 4 компонента:

### 1.1. FFmpeg и FFprobe с аппаратным ускорением
* **Пути на macOS:** `/opt/homebrew/bin/ffmpeg` и `/opt/homebrew/bin/ffprobe`
* **Установка:**

  * Кодирование H.264: использовать `-c:v h264_videotoolbox -b:v 8000k` (для 16:9 Full HD) или `-b:v 6500k` (для 9:16 Shorts).

### 1.2. Python-окружение для графики и аудиоанализа
* **Необходимые пакеты:** `Pillow` (генерация титров, плашек, инфографики), `numpy` (пофазовый анализ звука и детектор тишины с шагом 50 мс).
* **Установка:**
  ```bash
  python3 -m pip install pillow numpy
  ```
* *(На текущей рабочей машине готовый интерпретатор с Pillow и NumPy лежит по пути: `/Users/artemtysenko/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/bin/python`)*.

### 1.3. Движок транскрибации (Whisper)
* **Установка:** `pip install faster-whisper` или `mlx-whisper` (для Apple Silicon).
* **Формат выгрузки:** обязательно сохранять `.json` (с сегментами `segments: [{start, end, text}]`) и `.srt`.

> [!WARNING]
> **Почему нельзя рисовать текст через фильтр `drawtext` в FFmpeg:**
> В современных сборках Homebrew FFmpeg (v8/v9) фильтр `drawtext` часто отсутствует (`No such filter: 'drawtext'`), а кроме того, он не умеет делать стеклянные подложки (Glassmorphism), закруглённые углы, градиенты, тени и бейджи.
> **Золотой стандарт:** ВСЯ графика, плашки, субтитры и инфографика генерируются через **Python Pillow** как прозрачные `PNG (RGBA)` и накладываются через фильтр `overlay` с плавным `fade` по альфа-каналу!

## 2. Этап 1: Транскрибация и Пофазовый Аудио-Детектор (точность 50 мс)

### 2.1. Главная ловушка Whisper, о которой должна знать нейросеть
Таймкоды в `.srt` и `.json` от Whisper **НЕЛЬЗЯ использовать вслепую для резки видео**:
1. Если спикер замолчал на 8 секунд, посмотрел в конспект и начал фразу заново, Whisper часто включает эти 8 секунд тишины внутрь сегмента (`[45.42 -> 67.52]`).
2. Whisper может обрезать окончание последнего слова на `0.15–0.25 сек` раньше, чем затухнет голос.

### 2.2. Обязательный скрипт детекции реальных границ речи и тишины (50 мс RMS)
Перед тем как резать любой файл вокруг оговорки, дубля или склейки, нейросеть запускает этот скрипт на нужном диапазоне секунд:

```python
import subprocess
import numpy as np

def find_speech_blocks(video_path: str, ranges: list, threshold: float = 0.012):
    """
    Анализирует аудиодорожку с шагом 50 мс (0.05 сек) и выводит точные
    интервалы РЕЧИ (SPEECH) и ТИШИНЫ (SILENCE).
    """
    cmd = [
        "/opt/homebrew/bin/ffmpeg", "-v", "error",
        "-i", video_path,
        "-vn", "-ac", "1", "-ar", "16000", "-f", "f32le", "pipe:1"
    ]
    raw = subprocess.check_output(cmd)
    audio = np.frombuffer(raw, dtype=np.float32)
    sr = 16000
    step = int(0.05 * sr)  # окно 50 мс

    for label, (t0, t1) in ranges:
        print(f"=== {label} ({t0:.2f}s .. {t1:.2f}s) ===")
        s0, s1 = int(t0 * sr), min(len(audio), int(t1 * sr))
        in_speech = False
        b_start = t0
        for idx in range(s0, s1, step):
            chunk = audio[idx:idx + step]
            rms = np.sqrt(np.mean(chunk ** 2)) if len(chunk) else 0.0
            t = idx / sr
            is_sp = rms > threshold
            if is_sp != in_speech:
                tag = "SPEECH " if in_speech else "SILENCE"
                if t - b_start >= 0.15:
                    print(f"  {tag}: {b_start:6.2f}s -> {t:6.2f}s (длит: {t - b_start:4.2f}s)")
                b_start = t
                in_speech = is_sp
        tag = "SPEECH " if in_speech else "SILENCE"
        print(f"  {tag}: {b_start:6.2f}s -> {t1:6.2f}s (длит: {t1 - b_start:4.2f}s)")
```

### 2.3. Правило «Дыхательного зазора» (Audio Padding)
* **Начало фразы (`start`):** резать за **`0.15 – 0.25 сек` ДО** начала блока `SPEECH` (в зоне чистой тишины `SILENCE`), чтобы не съесть первый вдох и первую букву.
* **Конец фразы (`end`):** резать через **`0.20 – 0.30 сек` ПОСЛЕ** окончания блока `SPEECH` (в зоне `SILENCE`), чтобы полностью прозвучали глухие согласные на конце слова.
* **Проверка ложной склейки:** если между концом фразы и словом *«Ещё раз»* нет окна `SILENCE` (спикер сказал *«...и преобразовываю ещё раз»* слитно без паузы), резать на предыдущей чистой паузе до начала этого предложения!

## 3. Этап 2: Двухкамерный Мультикам-Монтаж (16:9 Уроки и Подкасты)

### 3.1. Сопоставление камер и проверка синхрона
Когда на диске лежат две папки — **`Общий`** (широкий план) и **`Крупный`** (портретный план 3/4):
1. Сравниваем длительности всех файлов через `ffprobe`: парные файлы имеют одинаковую длительность (разница `< 0.1 сек`).
2. Проверяем пофазовый сдвиг через кросс-корреляцию (`numpy.correlate`) первых 40 секунд аудио. Если файлы выведены с одного таймлайна DaVinci Resolve, лаг равен `0 samples (0.0000 sec)`.
3. Проверяем частоту кадров (`fps`) обоих исходников через `ffprobe`. Очень часто **Общий план снят в `50 fps`**, а **Крупный план — в `25 fps`**. Поэтому в фильтре FFmpeg на оба потока **ОБЯЗАТЕЛЬНО** ставится `fps=25`.

### 3.2. Режиссёрские правила переключения планов (Как монтировать как на ТВ)
1. **Правило маскировки склеек (Zero Jump-Cuts):**
   * На **каждом** вырезанном дубле, запинке или технической паузе **ОБЯЗАТЕЛЬНО меняется камера** (`Общий` $\rightarrow$ `Крупный` или `Крупный` $\rightarrow$ `Общий`).
   * Зритель воспринимает смену ракурса как живую режиссёрскую перебивку, и место склейки становится **на 100% незаметным**.
2. **Ритм внутри длинных непрерывных кусков:**
   * Нельзя держать один статичный план дольше 45–50 секунд.
   * Каждые **20–40 секунд** (строго на границе предложений в паузе `> 0.35 сек`) переключаем план:
     * **Общий план (~65–70% времени):** начало и финал урока, объявление темы, диктовка определений под запись, перечисление списков, моменты, когда спикер опускает глаза в конспект на столе.
     * **Крупный план (~30–35% времени):** личные истории из жизни, эмоции, шутки, крылатые цитаты, мотивация учеников и **упражнения на артикуляцию/скороговорки** (чтобы ученик крупно видел работу губ).

### 3.3. Архитектура быстрого рендера Мультикама (21x скорость вместо 0.5x!)

> [!CAUTION]
> **КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНО** подавать 15-минутный 4K-файл один раз на вход FFmpeg и делать внутри `filter_complex` 25 веток `trim=start=...` + `concat`. В этом случае FFmpeg будет декодировать 4K-файл с 0-й секунды 25 раз подряд, и рендер займёт 40 минут!

**Правильная однопроходная архитектура (Single-Pass Overlay Switching):**
1. Урок делится только на **крупные непрерывные чистовые блоки (`TAKES`)** между вырезанными ошибками (обычно в 15-минутном уроке всего 3–4 таких блока).
2. Каждый блок подаётся с быстрым аппаратным поиском:
   `-hwaccel videotoolbox -ss {t_start} -t {dur} -i WIDE.mp4`
   `-hwaccel videotoolbox -ss {t_start} -t {dur} -i CLOSE.mp4`
3. Внутри блока **аудио вообще не режется** (`[0:a]aresample=48000` идёт одним непрерывным куском без единой склейки!), а видео переключается между `[wide]` и `[close]` в один проход через фильтр `overlay` с параметром `enable`:

```python
filter_complex = (
    f"[0:v]fps=25,scale=1920:1080:flags=lanczos,format=yuv420p,setpts=PTS-STARTPTS[wide];"
    f"[1:v]fps=25,scale=1920:1080:flags=lanczos,format=yuv420p,setpts=PTS-STARTPTS[close];"
    f"[wide][close]overlay=0:0:shortest=1:enable='between(t,22.2,41.3)+between(t,63.5,72.84)'[vout];"
    f"[0:a]aresample=48000,asetpts=PTS-STARTPTS[aout]"
)
```
4. Готовые чистовые блоки склеиваются через `-f concat -c:v copy -af loudnorm=I=-16:TP=-1.5:LRA=11` за 3 секунды без перекодирования видео!

## 4. Этап 3: Вирусные Рилсы / Shorts (9:16, `1080x1920`) без перекрытия лица

### 4.1. Как отбирать фрагменты для вирусных Reels из длинных подкастов/уроков
ИИ сканирует транскрибацию и ищет законченные микро-истории длительностью **35–65 секунд**, содержащие:
* **Сильный хук в первые 3 секунды** (экстремальная деталь: *«В Сургуте в −35°C замерзала даже камера...»*, *«Муж выбежал с ружьём...»*, *«Пётр I лично написал первый репортаж...»*).
* **Драматургию (Завязка $\rightarrow$ Кульминация $\rightarrow$ Вывод/Мораль)** или **Чёткий фреймворк** (*«7 критериев новости»*, *«5 главных правил интервью»*).

### 4.2. Математика кадрирования 16:9 $\rightarrow$ 9:16 и Карта Безопасных Зон (Safe Zones)

При переводе горизонтального исходника (`3840x2160` или `1920x1080`) в вертикальный кадр **`1080x1920`** экран жестко делится на **4 неприкосновенные зоны**:

```
+---------------------------------------+  Y = 0
|      1. ВЕРХНЯЯ ЗОНА ХУКА / ШАПКИ     |
|   (Заголовок ролика, бейдж ● В ЭФИРЕ) |  Y = 90 .. 320 px
+---------------------------------------+  Y = 340
|                                       |
|        2. ЗОНА ЛИЦА И ЭМОЦИЙ          |
|     (Глаза спикера: Y = 580..720)     |
|   (Подбородок спикера: Y = 850..940)  |
|                                       |
|   ⛔ ЗАПРЕТНАЯ ЗОНА ДЛЯ ЛЮБОГО ТЕКСТА |  Y = 340 .. 1250 px
|          И ПЛАШЕК (910 px чистоты!)   |
|                                       |
+---------------------------------------+  Y = 1260
|     3. НИЖНЯЯ ЗОНА ПЛАШЕК И ТИТРОВ    |
|  (Динамические карточки, тезисы, гео) |  Y = 1280 .. 1620 px
|  (Лежит на уровне груди/стола спикера)|
+---------------------------------------+  Y = 1640
|   4. МЁРТВАЯ ЗОНА ИНТЕРФЕЙСА СОЦСЕТЕЙ |
|  (Описание Reels/Shorts, кнопки лайка)|  Y = 1640 .. 1920 px
+---------------------------------------+  Y = 1920
```

> [!IMPORTANT]
> **Железное правило защиты лица:**
> 1. Никакая плашка в формате `9:16` **НИКОГДА** не должна попадать в диапазон **`Y = 340 .. 1250 px`**.
> 2. Верхняя плашка-хук всегда рисуется в **`Y = 100 .. 310 px`**.
> 3. Нижние сменяющиеся смысловые карточки рисуются строго в **`Y = 1280 .. 1600 px`**, `X = 60 .. 940 px` (оставляя справа запас под иконки лайков/репостов соцсетей).

### 4.3. Динамический зум и маскировка склеек в Reels (9:16)
Если из 4K-исходника (`3840x2160`) вырезается вертикальный кадр `9:16`:
* **Базовый план (Wide 9:16):** вырезается прямоугольник `w=1215:h=2160:x={center_x - 607}:y=0` и масштабируется до `1080x1920`.
* **Крупный план (Zoom-In 1.18x на ключевых мыслях и склейках):** вырезается `w=1026:h=1824:x={center_x - 513}:y=120` и масштабируется до `1080x1920`.
* *(Либо, если есть вторая камера `Крупный`, в 9:16 чередуются кропы с первой и второй камеры!).*

## 5. Этап 4: Генерация Эфирной Графики и Инфографики для Курсов (16:9, `1920x1080`)

### 5.1. Где размещать инфографику в горизонтальном уроке (`1920x1080`), чтобы не закрывать спикера
Посмотри на композицию наших кадров (`Общий` и `Крупный`):
* **Ирина Витальевна сидит в правой половине кадра** (`X = 920 .. 1720 px`).
* **Левая половина кадра (`X = 80 .. 880 px`)** — это размытый фон шкафа и стола!
* Это даёт нам **идеальную телевизионную сетку (Split-Screen TV Layout)**:
  1. **Нижний титр спикера (Lower Third):** `X = 90 .. 920 px`, `Y = 860 .. 990 px` (появляется на 3–11 секунде урока).
  2. **Боковая карточка инфографики (Правило / Дата / Цитата / Термин под запись):**
     * Координаты: **`X = 80 .. 860 px`**, **`Y = 180 .. 780 px`** (слева от спикера!).
     * Когда спикер говорит *«Запишем определение: Журналистика — это...»* или называет историческую дату (*«13 января 1703 года — День российской печати»*), слева плавно всплывает премиальная карточка с этим текстом, а лицо и руки спикера справа остаются **полностью открытыми**!
  3. **Полноэкранная карточка «Домашнее задание» в финале урока:**
     * Либо крупный блок слева `X = 80 .. 920 px, Y = 140 .. 920 px` с чек-листом задания, пока спикер диктует его справа.

### 5.2. Эталонный Python-генератор карточек инфографики (Pillow RGBA)

```python
from PIL import Image, ImageDraw, ImageFont

FONT_BOLD = "/System/Library/Fonts/Supplemental/Arial Bold.ttf"
FONT_REG  = "/System/Library/Fonts/Supplemental/Arial.ttf"

def create_course_card_16x9(
    out_path: str,
    badge_text: str,
    title_lines: list[str],
    body_lines: list[str],
    accent_color=(245, 180, 60, 255) # Янтарное золото #F5B43C
):
    """
    Создаёт прозрачный Full HD (1920x1080) оверлей с карточкой инфографики
    в левой безопасной зоне (X=80..860), не перекрывающей спикера справа.
    """
    img = Image.new("RGBA", (1920, 1080), (0, 0, 0, 0))
    draw = ImageDraw.Draw(img)

    # Расчёт высоты карточки под количество строк
    x0, y0, x1 = 80, 220, 860
    card_h = 140 + len(title_lines) * 48 + len(body_lines) * 38
    y1 = y0 + card_h

    # Мягкая тень + тёмно-сапфировая подложка (#0B1222)
    draw.rounded_rectangle([x0+6, y0+8, x1+6, y1+8], radius=22, fill=(0, 0, 0, 110))
    draw.rounded_rectangle([x0, y0, x1, y1], radius=22, fill=(11, 18, 34, 238), outline=(245, 180, 60, 190), width=2)

    # Вертикальная акцентная полоса слева
    draw.rounded_rectangle([x0, y0, x0+12, y1], radius=6, fill=accent_color)

    # Бейдж сверху карточки
    f_badge = ImageFont.truetype(FONT_BOLD, 20)
    f_title = ImageFont.truetype(FONT_BOLD, 34)
    f_body  = ImageFont.truetype(FONT_REG, 26)

    badge_w = int(draw.textlength(badge_text, font=f_badge)) + 36
    draw.rounded_rectangle([x0+34, y0+26, x0+34+badge_w, y0+62], radius=8, fill=(225, 29, 72, 240))
    draw.text((x0+52, y0+32), badge_text, font=f_badge, fill=(255, 255, 255, 255))

    # Заголовок карточки
    curr_y = y0 + 82
    for line in title_lines:
        draw.text((x0+34, curr_y), line, font=f_title, fill=(255, 255, 255, 255))
        curr_y += 46

    curr_y += 12
    # Разделительная тонкая линия
    draw.line([(x0+34, curr_y), (x1-34, curr_y)], fill=(255, 255, 255, 45), width=1)
    curr_y += 18

    # Основной текст (определение / тезисы)
    for line in body_lines:
        draw.text((x0+34, curr_y), line, font=f_body, fill=(235, 240, 248, 255))
        curr_y += 38

    img.save(out_path)
```

### 5.3. Как накладывать несколько PNG-карточек в один проход без зависания FFmpeg

> [!CAUTION]
> **Правило №1 против вечного цикла (`-loop 1`):**
> Если подать `-loop 1 -i card.png` без ограничения длительности `-t {dur}`, FFmpeg никогда не остановится после окончания видео!
> **Всегда** ставь `-loop 1 -t {dur} -i card.png` на каждую плашку и добавляй `:shortest=1` в фильтр `overlay`!

Пример наложения плашки с плавным появлением (`fade in` 0.35 сек) и исчезновением (`fade out` 0.35 сек) на интервале `[t_in, t_out]`:
```python
# Пусть плашка должна висеть с 10.0 до 22.0 секунды сегмента длительностью dur:
t_in, t_out = 10.0, 22.0
# Входы FFmpeg: -loop 1 -t {dur} -i card.png
# Внутри filter_complex:
f"[2:v]format=rgba,fade=t=in:st={t_in}:d=0.35:alpha=1,fade=t=out:st={t_out - 0.35}:d=0.35:alpha=1[card1];"
f"[base][card1]overlay=0:0:shortest=1:enable='between(t,{t_in},{t_out})'[v_next];"
```

## 6. Пять железных заповедей отладки (Чек-лист для нейросети)

1. **Заповедь `python3` и `f-strings`:**
   * Системный `/usr/bin/python3` на macOS — это Python 3.9, который падает с `SyntaxError: f-string expression part cannot include a backslash`, если внутри `{...}` есть обратный слэш `\"`. Никогда не пиши `\"` внутри `{...}` в `f-string`.
2. **Заповедь чистого старта (`setpts=PTS-STARTPTS`):**
   * После любого `trim`, `atrim` или входного `-ss` всегда ставь `setpts=PTS-STARTPTS` (для видео) и `asetpts=PTS-STARTPTS` (для аудио) перед фильтрами `fade` / `afade` / `overlay`.
3. **Заповедь цветового профиля (`bt709` vs `LUT`):**
   * Перед рендером проверь исходник через `ffprobe`.
